# MCP 保险库写入权限设计

状态：方案已确认，待实现。

允许 Agent 通过 MCP 新增和修改 OpenKeylet 保险库项目，包括替换已有密码、Token 和 SSH 私钥。用户在桌面端配置允许写入的文件夹名称。这里的文件夹是保险库项目的分组字段。

## 权限规则

写入权限默认关闭，允许名单默认为空。打开开关且名单中至少有一个有效名称时，Agent 才能在指定文件夹内写入。首版的配置对连接本机 OpenKeylet 的所有 Agent 生效，不按 Agent 单独授权。

| 操作 | 放行条件 |
| --- | --- |
| 新增项目 | 目标文件夹在允许名单内 |
| 修改项目 | 从保险库读取的当前文件夹在允许名单内 |
| 移动项目 | 当前文件夹和目标文件夹均在允许名单内 |
| 删除项目 | 首版不提供 MCP 删除工具 |

文件夹按完整名称匹配。「开发」不会自动授权「开发/生产」。添加名称时去除首尾空白，拒绝空名称和重复项。文件夹改名时，用户需要显式更新名单。

写入权限独立于项目的查询、使用和秘密可见性。允许写入不会让隐藏字段变为可读。写入结果可返回项目 ID、模块 ID、项目版本号和操作状态，不返回秘密；错误信息也不能回显秘密值。

## 给 Agent 的写入功能介绍

功能上线后，MCP 的写入工具说明应向 Agent 提供下面的字段清单。下表中的英文标识是现有模块类型，最终调用参数以 MCP 工具声明为准。

只在用户授权的文件夹内新增或修改项目。新增时填写项目名称、类型和目标文件夹，可补充公开用途。公开用途是项目说明，不要在里面存放密码、Token 或私钥。修改时用项目 ID 定位，只提交要更新的字段。无法确定目标项目或必要的凭据信息时，先澄清，避免猜测。

| 要保存的项目 | 可用的预设字段 | 填写说明 |
| --- | --- | --- |
| SSH | 主机或 IP `host`、端口 `port`、账号 `username`、密码 `password`、SSH 私钥 `privateKey`、私钥口令 `passphrase` | 主机填写域名或 IP，端口用整数，标准 SSH 端口为 22。密码登录填写账号和密码。私钥登录填写账号和可用的 SSH 私钥，有口令时写入单独的口令字段。 |
| API | 服务 URL `url`、API 凭据 `apiCredential`，或 Basic 认证所需的账号 `username` 和密码 `password` | 令牌或 API Key 写入 API 凭据。服务 URL 可以包含 API 版本路径，用于保存服务基础地址。 |
| 登录 | 账号 `username`、密码 `password`，按需添加 TOTP 设置密钥 `totp` | 网站匹配使用项目的网站匹配规则。TOTP 字段保存设置密钥。 |
| 扩展字段 | 自定义字段 `customSecret` | 提供字段名和值，例如 `team_id`、`secondary_token`。已有对应预设时优先用预设。自定义字段按秘密加密保存，默认对 Agent 隐藏。 |

### 可修改范围与可见性

在可写文件夹内，Agent 可以自行决定新增和修改项目内容，包括名称、公开用途、项目类型、SSH 主机和端口、API 服务 URL、网站匹配规则、认证方式及凭据。目标变更不要求另建项目，也不要求同时替换原凭据；未提交的字段按下述局部更新规则保留。后端执行必要的数据合法性和字段组合校验，不额外设置目标变更禁令。实际连接时仍遵循已有的连接目标和协议安全校验。

Agent 可以替换秘密，但不能修改字段的 Agent 可见性。新增秘密字段默认隐藏，已有字段保持原可见性；包含可见性修改的请求应拒绝，不能通过更换模块类型等方式使旧的隐藏值变为可读。写入权限也不允许 Agent 修改写入总开关或允许名单。

自定义字段名不能与预设字段或同一项目内的其他字段重复。自定义字段只保存附加信息，不会自动参与 SSH/API 认证或连接配置。MCP 客户端如果以明文提交新值，该值已经经过调用客户端，请勿在聊天说明中复述。

### 认证方式与模块更新

- SSH 明确选择密码或私钥认证；即使同时保存两类凭据，也按选定方式使用。密码认证需要账号和密码，私钥认证需要账号和可用私钥。
- API 明确选择 Bearer Token、API Key 或 Basic。API Key 还需指定请求头名称，例如 `X-API-Key`；Basic 使用账号和密码。服务 URL 可包含 API 版本路径。
- 新增模块提交模块类型、名称和值；修改已有模块使用稳定的模块 ID 定位，不按显示名称猜测。模块 ID 必须属于指定项目。
- 修改请求使用项目 ID 和预期版本号，只提交需要更新的内容。未提交字段保留原值，不通过空值隐式删除项目或模块；SSH 口令关联处理是下面明确规定的例外。
- 工具声明须明确参数类型、必填组合和新增/修改操作结构。未知字段及不合法的字段组合应返回不含秘密的错误。

### SSH 私钥与口令

这里的口令用于解锁 SSH 私钥，与 SSH 登录密码是两个独立字段。

| 更新内容 | 处理规则 |
| --- | --- |
| 不修改私钥，也不提交口令 | 保留原私钥和口令 |
| 替换为无口令私钥 | 校验私钥，成功后自动清除旧口令 |
| 替换为加密私钥 | 必须同时提交对应口令，不自动沿用旧口令；验证能解锁后保存 |
| 只修改口令 | 在后端用现有私钥验证，匹配才保存；不会重新加密原私钥 |
| 私钥格式错误或口令不匹配 | 整次修改不生效，保留原数据 |

私钥与口令及同次请求内的其他字段一起原子保存，不能出现私钥已更新而口令或其他字段保存失败的部分状态。验证过程不向 Agent 返回旧私钥或口令。

### 写入能力查询与项目定位

提供不含秘密的写入能力查询，告诉 Agent：当前是否开启写入、允许的文件夹、支持的新增/修改/移动操作、支持的项目类型和模块、字段参数及认证方式，以及不能删除、不能修改可见性、不返回秘密等限制。该查询不修改任何授权。

已有项目继续遵循原有查询权限，返回允许查询的项目 ID、模块 ID 和版本号等信息。不可查询的项目不会因为所在文件夹可写而变得可查询。Agent 无法取得修改所需的 ID 或版本号时应澄清，不猜测目标。

新增成功后返回项目 ID、新增模块 ID、版本号和状态；修改成功后返回项目 ID、相关模块 ID、新版本号和状态。响应不包含秘密值。

### 调用信息示例

以下为拟定接口的信息示意，不是已经上线的 MCP 工具名称或最终 JSON 参数。实现时工具声明应承载同样的信息。

```text
新增项目：
  名称：开发服务器
  文件夹：Agent 管理
  类型：SSH
  认证方式：私钥
  新增模块：
    host：192.0.2.10
    port：22（整数）
    username：deploy
    privateKey：〈新私钥内容，无口令〉
    customSecret：名称 team，值 研发组

成功结果：
  项目 ID：item-123
  版本号：1
  模块 ID：host=m-host，port=m-port，username=m-user，
           privateKey=m-key，team=m-team
  状态：成功

替换私钥：
  项目 ID：item-123
  预期版本号：1
  修改模块：m-key，值 〈新的无口令私钥〉
  其他字段：不提交，保持原样

成功结果：项目 ID item-123，模块 ID m-key，版本号 2，状态成功
```

`team` 只保存附加信息，不参与 SSH 连接。若新私钥有口令，替换请求必须同时提交对应口令模块：已有模块按 ID 修改，不存在则新增。

API 认证示例：

| 选择的认证方式 | Agent 提交的信息 | 使用时的请求头示意 |
| --- | --- | --- |
| Bearer Token | 服务 URL、认证方式、`apiCredential` | `Authorization: Bearer <Token>` |
| API Key | 服务 URL、认证方式、请求头名称 `X-API-Key`、`apiCredential` | `X-API-Key: <Token>` |
| Basic | 服务 URL、认证方式、`username`、`password` | `Authorization: Basic <账号密码的编码>` |

## 并发与原子保存

每个项目具有版本号，查询时返回。修改和移动必须提交预期版本号；保存时与当前版本比较，不一致则拒绝，提示项目已变更，需重新查询后修改，不能自动覆盖或自动重试旧请求。

例如，两个 Agent 都基于版本 7 修改同一项目，先保存的成功，版本变为 8；后保存的仍携带版本 7，应收到冲突错误。桌面端等其他写入路径对项目的修改也必须更新版本号，才能发现跨入口的并发冲突。

同一次请求的全部字段必须校验通过才保存。最新权限检查、项目版本比较、全部字段更新和版本递增须作为同一次原子操作完成；失败时项目内容和版本都保持不变。每次成功修改递增项目版本号，并返回新版本号。

## 设置界面

在 **设置 → Agent 接入** 的客户端连接设置下方增加 **保险库写入权限**。

```text
保险库写入权限

允许 Agent 新增和修改项目                         [关闭]
允许修改指定文件夹内的项目内容，包括连接目标和凭据。

可写入的文件夹
  Agent 管理                                     [移除]
  开发环境                                       [移除]
  [＋ 添加文件夹]
```

点击「添加文件夹」后，可以选择已有文件夹，也可以输入新名称。点击「添加」才生效，因此可以为还没有项目的文件夹预先授权。点击「移除」立即撤销该名称的写入权限，已有项目和凭据照常保留。

总开关关闭时保留名单，并显示「当前禁止写入」。重新开启后恢复原有授权范围。名单为空时显示「尚未添加可写入的文件夹」，此时写入仍被拒绝。

列表下方说明：「对连接本机 OpenKeylet 的所有 Agent 生效。新增项目必须选择可写文件夹。移动项目时，原文件夹和目标文件夹都必须可写。Agent 不能删除项目或修改字段可见性，写入结果不会返回秘密。」

## 后端检查与验收

每次写入时使用保险库当前的总开关、名单和项目分组做判断。修改操作以保存的项目为准，调用方不能在请求里声明一个可写的原文件夹来取得权限。权限检查和项目写入应在同一次保险库更新中完成，让并发修改或权限撤销不会产生检查与保存之间的空档。

- 默认关闭、名单为空和目标文件夹为空时，MCP 写入均被拒绝。
- 名单只包含「Agent 管理」时，可以在其中新增项目及替换密码、Token 和 SSH 私钥，但不能写入「个人」或「Agent 管理/生产」。
- 把「个人」的项目移动到「Agent 管理」会被拒绝。把「Agent 管理」的项目移到名单外也会被拒绝。原、目标文件夹同时在名单内时允许移动。
- 关闭总开关或移除文件夹后，已连接的 Agent 下一次写入也会被拒绝。
- 成功响应、错误和活动记录均不包含提交的秘密值。桌面端原有编辑功能继续可用。

- 在可写文件夹内修改 SSH 主机/端口、API URL、网站匹配或项目类型，合法请求可成功，不要求另建项目；未提交的凭据保持不变。
- Agent 替换秘密时原可见性不变，新增秘密字段默认隐藏；尝试修改可见性或写入授权配置被拒绝。
- 无口令私钥替换会清除旧口令；加密私钥替换必须提交匹配口令；只改口令须与原私钥匹配。缺少必要口令、错误口令、无效私钥均整次回滚。
- SSH 同时保存密码和私钥时按指定认证方式执行；API 的 Bearer、API Key 自定义请求头和 Basic 使用正确的认证配置。自定义字段不自动参与认证。
- 模块按 ID 精确修改，其他模块保持不变；跨项目模块 ID、重复自定义字段名、未知参数和不合法字段组合被拒绝。
- 能力查询返回实际可写范围和支持字段，不包含秘密；写入授权不扩大已有项目查询范围。新增及修改结果提供后续操作所需的 ID 和版本号。
- 两个请求使用同一版本号修改时，只能一个成功，另一个收到冲突；桌面端先修改后，持有旧版本的 MCP 请求同样被拒绝。
- 一次请求混合有效与无效字段，项目全部内容和版本号保持原样；失败的移动也不改变文件夹。
- 写入提交时已撤权或项目已被移动至不可写文件夹，请求被拒绝，不能使用先前查询得到的授权状态完成保存。
- 成功响应、校验错误、冲突错误及活动记录不包含新旧秘密；版本冲突不返回项目秘密快照。
