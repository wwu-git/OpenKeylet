# MCP 保险库写入权限设计

状态：首版已实现并完成本地验收，见 [验收报告](mcp-vault-write-acceptance.md)。本文定义首版行为；示例为接口信息示意，最终参数以 MCP 工具声明为准。

## 1. 范围与权限

Agent 可通过 MCP 新增、修改和移动保险库项目，包括替换密码、Token、SSH 私钥，以及修改名称、公开用途、项目类型、连接目标、网站匹配和认证方式。修改目标不要求另建项目或替换凭据；后端仍执行数据合法性、字段组合及实际连接时的协议安全校验。首版不提供删除项目工具。通用 API 写入范围为第 2 节的三种认证；OCI 的例外见第 6 节。

**写入总开关和文件夹白名单只限制 Agent 通过 MCP 写入，不限制客户端手动新增、修改和移动。** 配置对连接本机 OpenKeylet 的所有 Agent 生效，不按 Agent 单独授权。文件夹指项目的分组字段。

写入默认关闭，白名单默认为空。开启且名单非空后，按以下规则放行：

| 操作 | 条件 |
| --- | --- |
| 新增 | 目标文件夹在名单内 |
| 修改 | 保险库中项目的当前文件夹在名单内 |
| 移动 | 当前、目标文件夹都在名单内 |

名称按完整名称匹配，不继承子文件夹权限，例如「开发」不包含「开发/生产」。添加名称时去除首尾空白，拒绝空名称和重复项；文件夹改名后须显式更新名单。空文件夹不获授权。

写入权限与查询、使用权限独立，不扩大原有查询范围，不允许 Agent 修改写入配置或字段可见性。新增秘密字段默认隐藏，已有字段保持可见性，不能通过更换模块类型等方式公开旧秘密。成功响应、错误及活动记录均不得包含新旧秘密，也不返回冲突项目的秘密快照。客户端明文提交的新值已经经过调用客户端，Agent 不应在聊天中复述。

## 2. 字段与认证

新增项目必须提供名称、类型和文件夹，可填写公开用途；公开用途不得存放秘密。以下英文标识为模块类型，工具声明须明确参数类型、必填组合及新增/修改结构。

| 项目 | 可写模块 | 使用规则 |
| --- | --- | --- |
| SSH | `host`、`port`、`username`、`password`、`privateKey`、`passphrase` | 主机为域名或 IP，端口为整数（标准端口 22）。明确选择密码或私钥认证；即使两类凭据都有，也只按选定方式使用。两种方式均需账号。 |
| API | `url`、`apiCredential`、`username`、`password` | URL 可含 API 版本路径；认证配置见下表。 |
| 登录 | `username`、`password`、`totp` | TOTP 保存设置密钥；网站匹配使用项目的网站匹配规则。 |
| 自定义 | `customSecret` | 提供名称和值，如 `team_id`、`secondary_token`；优先使用已有预设。按秘密加密保存，名称不得与预设或项目内其他字段重复。只保存附加信息，不自动参与认证或连接。 |

| API 认证方式 | 必需凭据/配置 | 请求头示意 |
| --- | --- | --- |
| Bearer Token | `apiCredential` | `Authorization: Bearer <Token>` |
| API Key | `apiCredential`、请求头名称 | `X-API-Key: <Token>`（名称示例） |
| Basic | `username`、`password` | `Authorization: Basic <账号密码的编码>` |

### SSH 私钥与口令

`passphrase` 用于解锁私钥，与登录密码独立。以下校验在后端执行，不返回旧私钥或口令。

| 更新内容 | 处理规则 |
| --- | --- |
| 私钥、口令都不提交 | 保留原值 |
| 替换为无口令私钥 | 校验成功后自动清除旧口令 |
| 替换为加密私钥 | 必须同时提交匹配口令，不沿用旧口令 |
| 只修改口令 | 用现有私钥验证，匹配才保存；不重新加密私钥 |
| 私钥无效、缺少必要口令或口令不匹配 | 整次请求失败，原数据不变 |

## 3. 查询、更新与并发

提供不含秘密的写入能力查询，返回开关状态、可写文件夹、支持的操作/项目类型/模块、字段参数、认证方式和限制。能力查询不改变授权；已有项目仍按原查询权限返回项目 ID、模块 ID 和版本号。无法确定目标、必要凭据或取得所需 ID/版本号时，Agent 应澄清，不猜测。

- 新增模块提交类型、名称和值；修改模块使用稳定的模块 ID，且该 ID 必须属于指定项目。
- 修改和移动提交项目 ID、预期版本号及需要变更的内容；未提交字段保留，不通过空值隐式删除项目或模块。无口令私钥替换时清除旧口令是明确例外。
- 未知参数、不合法字段组合和可见性修改请求均拒绝。整次请求全部校验通过才保存，不允许部分更新。
- 保存时从保险库读取真实的当前文件夹，不能信任调用方自报的原文件夹。最新权限检查、版本比较、字段更新和版本递增须在同一次原子操作中完成；失败时内容、文件夹和版本都不变。
- 版本不匹配则返回冲突，要求重新查询后修改，不自动覆盖或重试旧请求。例如两个请求基于版本 7 修改，仅先保存者成功并递增到 8。
- 客户端等其他入口的修改也更新版本号，但不受 MCP 白名单限制。关闭开关、移除授权或项目移出可写范围后，尚未提交的 MCP 写入按最新状态拒绝。
- 成功结果返回项目 ID、新增或相关模块 ID、项目新版本号和状态，不返回秘密。

### SSH 调用示例

```text
新增：名称=开发服务器，文件夹=Agent 管理，类型=SSH，认证方式=私钥
模块：host=192.0.2.10，port=22，username=deploy，
      privateKey=〈无口令私钥〉，customSecret={名称: team, 值: 研发组}
结果：项目 ID=item-123，版本=1，状态=成功，
      模块 ID={host: m-host, port: m-port, username: m-user,
               privateKey: m-key, team: m-team}

替换：项目 ID=item-123，预期版本=1，修改模块 m-key=〈新的无口令私钥〉
结果：项目 ID=item-123，模块 ID=m-key，版本=2，状态=成功
```

未提交内容保持原样，`team` 不参与连接。若换成加密私钥，须同时提交口令：已有口令模块按 ID 修改，没有则新增。

## 4. 设置界面

位置：**设置 → Agent 接入 → 客户端连接设置下方 → 保险库写入权限**。

```text
允许 Agent 新增和修改项目                         [关闭]
允许修改指定文件夹内的项目内容，包括连接目标和凭据。
可写入的文件夹
  Agent 管理                                     [移除]
  开发环境                                       [移除]
  [＋ 添加文件夹]
```

添加可选择已有文件夹或输入新名称，点击「添加」生效，允许预先授权尚无项目的文件夹；移除立即撤权，保留项目和凭据。关闭开关保留名单并显示「当前禁止写入」，重新开启恢复名单；名单为空显示「尚未添加可写入的文件夹」，仍禁止写入。

说明文案：「对连接本机 OpenKeylet 的所有 Agent 生效，不限制客户端手动操作。新增项目的目标文件夹、移动项目的原和目标文件夹都必须可写。Agent 不能删除项目或修改字段可见性，写入结果不会返回秘密。」

## 5. 验收清单

以下为验收要求，实际执行结果与测试范围见验收报告。

| 范围 | 必须覆盖的用例与结果 |
| --- | --- |
| 默认与匹配 | 关闭、空名单、空文件夹均拒绝；名单仅有「Agent 管理」时，可在其中新增、替换凭据，不能写「个人」或「Agent 管理/生产」；名称去空白、拒绝重复及改名后授权行为符合第 1 节。 |
| 移动 | 仅授权「Agent 管理」时，「个人」与其双向移动均拒绝；两端都获授权才成功；伪造原文件夹不能绕过检查。 |
| 撤权 | 已连接 Agent 也受最新开关、名单约束；提交前撤权或项目移出范围，写入失败。 |
| 手动操作 | 关闭或空名单时，客户端仍可在「个人」新增、修改并与「Agent 管理」双向移动；修改使旧版本 MCP 请求冲突。 |
| 修改范围 | 合法的主机/端口、URL、网站匹配、项目类型及认证方式修改成功，不要求另建项目；未提交凭据保留。 |
| 可见性与秘密 | 替换保持原可见性，新秘密默认隐藏；禁止改可见性、借模块类型公开旧秘密或改写入配置；响应、各类错误、活动记录不含新旧秘密。 |
| 私钥 | 覆盖第 2 节全部私钥/口令组合；失败时包括同请求其他字段在内全部回滚。 |
| 认证与自定义 | SSH 两类凭据并存时按选定方式使用；三种 API 认证发送正确请求头；自定义字段可新增修改，但不参与认证。 |
| 模块与参数 | 按 ID 精确更新，其他模块不变；跨项目模块 ID、重复自定义名称、未知参数和非法组合拒绝；省略与空值不隐式删除。 |
| 查询与返回 | 能力查询符合实际授权并包含字段说明；不扩大项目查询权限；成功返回后续操作需要的 ID、版本及状态，不含秘密。 |
| 并发与原子性 | 同版本并发仅一个成功；客户端修改也导致旧版本冲突；混合有效/无效字段或失败移动均不改变内容、文件夹和版本。 |
| 设置 | 添加已有/新文件夹、移除立即撤权、关闭保留名单、重开恢复、空名单提示均符合第 4 节。 |

## 6. 最小实现范围与复用

下表保留实现前的复用分析与最小改动范围，本次已按此完成；“现有基础”指开发前的状态。实现沿用保险库存储和执行器，只增加必要的 MCP 写入适配。

| 分类 | 现有基础 | 最小改动 |
| --- | --- | --- |
| 复用：存储 | `vault.rs` 的文件排他锁、锁内读取、原子文件替换、秘密加密和密码历史 | 权限、版本、合并、校验和保存进入同一次锁内更新；不另建数据库、锁服务或凭据存储。 |
| 复用：字段 | `model.rs` 的 `folder`、模块、可见性及 `customSecret`；`vault.rs::normalize_modules` 的名称/重复/端口校验 | 使用字符串名单，不建立文件夹实体；沿用模块校验、秘密默认隐藏及自定义字段保存。 |
| 复用：API | `executor.rs` 已支持 Bearer、API Key 请求头、Basic | MCP 参数映射已有配置，不新增认证执行器。 |
| 修改：局部保存 | `vault.rs::save_connection_inner` 面向完整编辑输入，会清理被移除模块的秘密 | 提取共用保存逻辑，MCP 在锁内读取原项目并合并局部变更；不能将局部请求直接当完整表单保存，也不能先查权限再另行加锁保存。 |
| 修改：版本 | 已有 `expected_updated_at` 冲突检查，客户端会传更新时间 | 复用比较机制，新增递增项目版本 `revision`，不是将时间戳当整数版本。客户端、备份合并等实际修改项目的入口统一维护，兼容旧数据。 |
| 新增：模块 ID | `ItemModule` 目前只有类型、名称、值和可见性，没有稳定 ID | 增加持久模块 ID，旧数据补齐；客户端编辑、排序和备份往返须保留 ID，不使用数组下标或显示名称代替。 |
| 修改：SSH 认证 | 执行器支持两种认证，但保存时按“有密码则密码，否则私钥”推导 | 增加显式认证方式输入并保存；旧项目保留兼容默认行为，不重写 SSH 执行器。 |
| 修改：私钥校验 | `commands.rs::decode_private_key` 已能解析私钥并验证口令，但位于 GUI 命令模块 | 提取共享函数供 GUI/MCP 调用，补齐第 2 节的关联更新规则，不新写密码学实现。 |
| 修改：查询 | `mcp.rs` 的搜索已有查询过滤和可见性处理，但响应没有项目 ID、模块 ID、版本 | 扩展允许查询的结果，保留原过滤和可见性规则，不借写入功能扩大查询范围。 |
| 新增：权限与工具 | 已有 MCP 路由和工具声明基础 | 增加能力查询、新增、修改三个工具；移动作为修改文件夹，不另设工具。新增锁内权限检查、严格参数及仅含 ID/版本/状态的响应。 |
| 修改：设置 | 已有 `Settings`、`SettingsPatch` 及客户端设置更新流程 | 添加默认关闭的开关、默认空名单和第 4 节 UI；配置只由客户端修改。 |
| 扩展：测试 | 已有并发写入、设置并发及生命周期测试 | 沿用测试设施补第 5 节用例，不搭建独立测试平台。 |

MCP 必须使用独立的精简请求结构，不能直接暴露 `ConnectionInput`：后者包含本地私钥文件路径、秘密删除列表等客户端专用参数。共享内部业务逻辑，但保留 MCP 和手动操作的权限边界；写入结果也不能直接返回完整项目对象。

### OCI 边界

当前 OCI 使用 `save_oci_connection` 和专用签名配置，通用保存入口会拒绝直接编辑 OCI 项目。不能仅把 OCI 传入通用保存函数，或移除这项保护来实现写入。

- 首版通用 MCP 写入不负责创建 OCI 签名项目、转换普通项目与 OCI 项目、替换 OCI RSA 签名私钥，或修改区域、租户/用户 OCID、公钥指纹和签名认证方式；这些仍通过客户端 OCI 专用流程处理。
- 对已有 OCI 项目，允许按相同文件夹权限和版本规则修改名称、公开用途、文件夹，以及独立的普通附加模块（例如密码、SSH 私钥、自定义字段）。只复用普通模块的校验和保存，不改变 OCI 签名配置。
- OCI 项目类型、签名认证方式及由区域推导的服务 URL 不由通用写入修改。保存附加模块时必须原样保留签名凭据、配置和派生 URL；同一次请求若夹带不支持的 OCI 修改，整次拒绝。
- 普通 `privateKey` 是 SSH 私钥，不能映射成 OCI 签名私钥；自定义字段即使命名为 `region` 或 `tenancy_ocid`，也只保存附加值，不改变 OCI 配置。
- 在能力说明中明确此例外。MCP 项目写入不修改 OCI 签名配置；运行时 `http_send` 的通用签名、目标边界和调用方式见 [OCI API 签名代执行](oci-api-request-signing.md)，两者权限独立。

最小实现是在共享保存逻辑中保留 OCI 数据、校验普通补丁，而非开发第二套 OCI 编辑或签名流程。验收须覆盖附加模块更新成功且 OCI 数据不变、禁止项整次回滚、SSH/OCI 私钥隔离，以及客户端 OCI 编辑仍可使用。

### 实施顺序与不做事项

1. 模型兼容与共享保存：模块 ID、项目版本、局部合并、共享私钥校验、显式 SSH 认证和 OCI 数据保留。
2. MCP 权限与接口：能力查询、新增/修改、查询元数据、严格请求及脱敏响应。
3. 客户端设置：开关、名单及提示，保持手动操作独立。
4. 增量验收：第 5 节及 OCI 用例；额外验证旧数据升级后 ID 稳定、备份往返保留 ID、各写入入口的版本维护。

首版不新增角色体系、逐 Agent 授权、逐字段授权、审批流、独立权限服务、文件夹数据库、移动专用工具或新认证框架。稳定模块 ID 和递增版本虽涉及模型兼容，但属于已确认功能，不以省略它们来缩减范围。
