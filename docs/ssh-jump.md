# SSH 单级跳板

目标是让内网项目 B 引用已有项目 A 作为公网跳板。A、B 分别使用自己的用户名和密码或私钥。命令执行、文件上传和下载复用同一个 SSH 连接入口。

## 连接与范围

```text
OpenKeylet → A 的 SSH 服务 → direct-tcpip 通道 → B 的 SSH 服务
```

OpenKeylet 在转发通道内直接与 B 完成 SSH 握手和认证。B 的私钥不上传到 A，不启用 SSH Agent 转发，不启动本地监听端口。A 必须允许 TCP 转发且能访问 B。B 的域名由 A 解析。

首版只支持一个跳板。A 必须是已启用且认证配置完整的直接连接项目。不能引用自身，也不能把已经使用跳板的项目作为 A。配置缺失、引用失效或转发失败时明确报错，不自动直连 B。

连接对象同时持有 A、B 的会话。正常结束先关闭 B 再关闭 A。握手、认证、转发、命令或传输失败，以及超时和取消，均须清理连接链。

## 项目配置与权限

B 保存跳板项目的稳定 ID，不复制 A 的凭据。项目改名不影响引用。编辑草稿取消时保留原配置，保存时执行后端校验，实际连接前再次校验 A 是否可用。

MCP 沿用 `ssh_run`、`ssh_upload` 和 `ssh_download`，调用 B 时使用其保存的连接路径。项目新增和修改沿用写入总开关、文件夹白名单及项目版本校验。引用 A 只要求 A 可使用，不要求对 A 有写入权限。普通自定义字段不参与跳板配置。

客户端使用步骤：

1. 保存 A 的主机、端口、用户名和认证方式，保持 A 为直接连接。
2. 编辑 B，在“SSH 连接”中选择“通过跳板项目”，选择 A 后保存。
3. 编辑 A，展开“本机主机身份信任”。读取候选指纹，与可信来源核对后勾选确认，并保存本机信任。
4. 编辑 B，以同样方式确认 B 的指纹。此时读取 B 的候选指纹会先通过已信任的 A。
5. 通过 MCP 对 B 执行命令或上传、下载文件。

跳板选择仅在保存项目后生效。关闭编辑器不修改已保存项目，未保存的修改沿用现有加密草稿逻辑。本机信任按钮是单独的立即生效操作，界面明确提示它不会被关闭编辑器撤销。新项目或尚未保存的端点、路由不能通过该面板确认指纹。

MCP 的 `items_create.sshJumpItemId` 可指定 A 的项目 ID。`items_update` 不提交此字段表示保留，提交 `null` 表示改为直接连接，提交项目 ID 表示改用该跳板。修改仍须提交最新 `expectedRevision`。`items_search` 返回引用 ID 及不可用状态，新增引用元数据不包含秘密，其他字段沿用原可见性规则。

## 本机主机信任

跳板连接的 A、B 均须具有已确认的主机公钥 SHA256 指纹。信任记录绑定项目 ID、主机与端口，目标覆盖参数不能继承其他地址的指纹。不同跳板后的同一个内网地址可以具有不同指纹。先验证 A 才使用 A 的凭据，再验证 B 才使用 B 的凭据。指纹缺失或变化时停止，不能自动接受。

查看指纹不代表已确认服务器身份。用户必须通过服务器控制台或管理员提供的可信值核对。探测 A 不发送认证凭据。经 A 探测 B 需要先信任并认证 A，但不认证 B。

信任记录由客户端或本地管理 CLI 管理，MCP 项目写入不能修改。记录仅留在本机，不随备份恢复自动信任。已有无跳板项目保留原直连兼容行为，本功能不宣称已经迁移所有旧项目的主机信任策略。

## 版本兼容

新增路由配置使用保险库格式 14。新版本可以读取格式 7 至 13，在下一次写入时升级。旧格式 13 程序不能读写已经升级的保险库，避免保存时丢弃未知路由字段而把跳板项目变成直接连接。升级前保留可用备份，不混用新旧程序管理同一个目录。

可移植备份继续使用现有格式。旧版的项目解码器拒绝未知字段，因此不能将含跳板字段的新备份静默恢复成直连项目。新版本仍兼容旧备份。主机信任记录不在可移植项目中。

## 无界面版管理命令

所有命令与 MCP 使用同一个绝对保险库目录。

```sh
export OPENKEYLET_DATA_DIR="$HOME/.local/share/openkeylet"
openkeylet ssh-trust list
openkeylet ssh-trust probe A的项目ID
openkeylet ssh-trust set A的项目ID A的主机 A的端口 经可信渠道核对的SHA256指纹
openkeylet ssh-trust probe B的项目ID
openkeylet ssh-trust set B的项目ID B的主机 B的端口 经可信渠道核对的SHA256指纹
```

上面的参数为占位说明，执行前替换为实际值。项目 ID 可通过 MCP 查询。探测只展示观测到的指纹，不自动保存。探测 B 前必须已确认 A 的信任记录。随后通过 MCP 对 B 执行命令或上传下载，程序按 B 保存的跳板引用连接。

移除指定端点的本机信任记录：

```sh
openkeylet ssh-trust remove B的项目ID B的主机 B的端口
```

这些管理命令不受 MCP 文件夹白名单约束。能以同一系统用户执行管理 CLI 的调用方具备更高权限，隔离仍由操作系统和部署环境负责。

## 备份恢复

项目跳板引用参与备份和内容比较。恢复先处理直接连接项目，建立备份 ID 到实际项目 ID 的映射，再重写并处理引用跳板的项目。A 被合并或生成冲突副本时，B 必须引用本次映射的 A。

缺少 A 的引用须保持不可用，不能因为与本机某个 ID 碰巧相同而绑定该项目，也不能清空成直连。重复恢复比较映射后的引用关系，不持续产生副本。重复来源 ID 的快照应在修改保险库前拒绝，不能任意选择一个来源。

## 设计取舍

设计比较了持有完整连接链的对象和以异步闭包包围操作的方案。采用前者，原因是现有命令执行与 SFTP 都能继续使用最终目标会话，连接生命周期集中管理。没有引入通用隧道框架、连接池或第二套文件传输实现。

实现由一个代理独占源码，另一个代理只读检查设计。未验证独立供应商模型配置，因此未进行跨供应商裁决。父任务负责检查实际 diff、运行验收并提交。

## 验收要求

使用本机临时保险库、两个 SSH 测试服务和模拟凭据，不访问真实主机或业务保险库。

| 场景 | 预期结果 |
| --- | --- |
| 经 A 执行命令 | 命令在 B 执行，A 仅转发。 |
| 上传和下载 | 文件存于 B，二进制内容往返一致。 |
| 两端独立认证 | 密码、私钥及混合方式使用各自凭据。 |
| A 主机密钥不匹配 | A 收到零次认证尝试，B 无连接。 |
| B 主机密钥不匹配 | A 可认证，B 收到零次认证尝试。 |
| A 拒绝转发、B 不可达 | 分阶段报错，不直连 B。 |
| 超时、取消及传输异常 | 两端连接与任务被清理。 |
| 自引用、多级、失效引用 | 保存或连接前拒绝。 |
| 备份冲突和重复恢复 | 引用正确，重复恢复不新增副本。 |
| 窄窗口和取消编辑 | 控件可用，取消不修改原配置。 |
