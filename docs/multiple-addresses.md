# 多主机和多服务 URL

普通项目的“主机 / IP”和“服务 URL”模块支持多个地址。每个模块只有一个默认地址，项目原有的端口、用户名和凭据由这些地址共用。

在编辑器中点击“添加地址”，填写地址后点击“设为默认”。删除默认地址会将剩余第一项设为默认。删除最后一项会保留一个空输入框。点击保存后修改才生效；关闭未保存的编辑会按现有草稿逻辑保留，不改变已保存项目。空白的其它地址、重复地址和无效服务 URL 无法保存。

未指定主机的 SSH 命令及文件传输使用默认主机。HTTP 请求省略 `url` 或传入相对路径时，使用默认服务 URL。要选择其它地址，SSH 传入 `host`，HTTP 传入完整的绝对 `url`。程序不会轮询地址，也不会在失败时自动尝试其它地址。现有 HTTP 重定向和运行时目标策略保持原样。

SSH 跳板项目 A 使用 A 的默认主机，目标项目 B 使用 B 的默认主机或调用明确传入的主机。A、B 各自认证。现有跳板连接按项目、主机和端口分别强制校验两端指纹。直接 SSH 连接沿用现有实现，尚未强制校验保存的主机指纹；多地址功能没有改变这个边界。

OCI API 项目的默认服务 URL 继续由区域生成，不保存多个地址。单次 `http_send` 可通过绝对 URL 选择同一区域的 OCI 服务，仍受 [OCI API 签名目标校验](oci-api-request-signing.md#请求和目标边界) 约束，不会自动切换地址。

## MCP 字段

`host` 和 `url` 模块的 `value` 是默认地址，`alternateValues` 是其它地址。模块稳定 ID、文件夹写入权限、`expectedRevision` 和不可修改可见性的规则继续适用。隐藏模块不会在查询结果中返回默认地址或其它地址。

新增模块示例。

```json
{
  "kind": "host",
  "value": "public.example.com",
  "alternateValues": ["10.0.0.20", "private.example.com"]
}
```

更新时省略 `alternateValues` 会保留原列表，传入 `[]` 会清空。`value` 始终是默认地址的完整替换。若要将现有其它地址设为默认，应同次提交新默认地址和剩余列表。

```json
{
  "id": "PROJECT_ID",
  "expectedRevision": 2,
  "modules": [{
    "id": "HOST_MODULE_ID",
    "value": "10.0.0.20",
    "alternateValues": ["public.example.com", "private.example.com"]
  }]
}
```

## 数据兼容

新版本使用保险库格式 15 和备份内容格式 9，保留旧格式读取能力。文件备份、GitHub 加密快照、冲突副本和重复恢复均包含地址列表。SSH 本机信任记录继续不随备份迁移。

旧程序不能写入新格式。桌面版、无界面版和其他共享保险库的主机应一起更新；更新后重连 MCP，以加载新增字段和工具说明。保留升级前备份，避免用旧程序覆盖新的多地址数据。
